# Game State

Current version: **0.19.0**

## Built
- Unity 2D project setup (Force Text serialization, Visible Meta Files, 2D editor mode).
- `DropScreen` scene (first scene in the build): the title screen. Shows the game name, a blinking "PRESS ANY KEY", and the version, then loads HomeScreen. Generated by `DropScreenSceneBuilder`.
- `HomeScreen` scene (second scene in the build): title, New Game, Continue, Settings, Quit, and the version label.
  - New Game deletes any saved battle and opens the Battle scene. Continue opens the Battle scene, which loads the save. Continue is disabled when there is no save. There is no "are you sure?" question before New Game replaces a save.
  - Settings panel: master volume, fullscreen, resolution, Back. Saved with PlayerPrefs through `GameSettings`.
  - The scene is generated by `HomeScreenSceneBuilder` (menu: KyubPon > Rebuild Home Screen Scene). Change the layout in that script, because rebuilding replaces the scene.
- Input goes through Unity's Input System package (`com.unity.inputsystem`). Menus work with mouse, keyboard (arrows + Enter), and controller using Unity's default UI actions.
- Press Start 2P pixel font in `Assets/Game/Fonts/PressStart2P/` (see `docs/Credits.md`).

- Unity's Pipeline package (`com.unity.pipeline`, experimental) is installed so the `unity` command-line tool can drive the open Editor: run menu items, enter Play mode, read the console, take screenshots. Remove its line from `Packages/manifest.json` if it is not wanted.

- Version tooling: `tools/Set-GameVersion.ps1` keeps the version identical in every file (see `docs/Releasing.md`).

- Git: one long-lived branch, `main`. Feature branches are merged into it and deleted.

## Audio
- `GameAudio` (in `Scripts/Core/`) is the sound player. It creates itself before the first scene loads, loops the soundtrack, and plays effects by name: `GameAudio.Play(GameSound.ButtonClick)`.
- Each name in the `GameSound` list is also a file name. Sound files are loaded from `Assets/Game/Audio/TemporaryDemo/Resources/DemoAudio/` (for example `ButtonClick.wav`, `Music.mp3`, and `HitChain1.wav` to `HitChain10.wav`).
- `ButtonSound` gives every menu button its hover and click sounds; the scene builders add it.
- Three volumes are saved in `GameSettings`: master (applied to the listener), music, and sound effects.
- **The sound files are temporary and are not in Git.** They are third-party files with unconfirmed licenses (see `docs/Credits.md`), so `Assets/Game/Audio/` is ignored by Git and exists only on Idan's PC. A missing file is silent and logs a warning. To remove the temporary audio, delete that folder; the code keeps working.
- Not done yet: the Audio Mixer and logarithmic volume scale described in CLAUDE.md. Volumes are plain 0 to 1 values on the audio sources.

## Block skins
- The four block skins live in `Assets/StreamingAssets/Content/Blocks/<Name>/<Name>.png` (RedBlock, BlueBlock, GreenBlock, YellowBlock). Size: 64 by 64 pixels, PNG, transparency allowed. Replace a file to change a skin.
- `BlockSkinLoader` (in `Scripts/Core/`) reads them at run time with sharp pixel scaling.
- The block folders hold only the PNG so far. The JSON data file described in CLAUDE.md is not there yet, because block data is still written in the battle code (`BattleCubeKind.cs`).

## Battle
The `Battle` scene (third scene in the build), generated by `BattleSceneBuilder` (menu: KyubPon > Rebuild Battle Scene). It began as a test page and is still a prototype of the real battle: one battle, no shop, events, or levels yet.
- Opened by New Game and Continue on the Home screen. BACK returns to the Home screen.
- Saving: the battle is saved after every turn, when a battle is dealt (New Game, RESET), when the grid size changes, and when ORDER is pressed between turns. "AUTOSAVING..." shows in the top-left corner for about a second each time (`AutosaveLabelSeconds` in `BattleScreen.cs`).
  - `BattleSave` writes one file, `BattleSave.json`, in `Application.persistentDataPath` (on Windows: `%USERPROFILE%\AppData\LocalLow\<company>\KyubPon\`). `BattleSaveData` lists what is saved: grid size, every block with its HP and square, both hands, turn number, destroyed counts, activation order, the result if the battle is over, and the positions seen so far (for the draw rule).
  - The save is never written in the middle of a turn. Quitting while a turn is playing brings the battle back as it was at the end of the turn before.
  - A finished battle stays saved, so Continue shows its result until RESET or New Game deals a new one.
  - A missing, damaged, or outdated file (`FormatVersion`) is logged as a warning and a fresh battle is dealt.
  - The save uses Unity's built-in `JsonUtility`, not Newtonsoft JSON as CLAUDE.md asks, because the Newtonsoft package is not installed yet.
- Grid size is changed with the on-screen arrows; the limits (minimum 5 by 4, maximum 12 by 8) are constants in `BattleGridSize.cs`.
- Turns: each turn the player drags one block onto an empty square, the enemy places one (drawn with an X), then every square activates in reading order starting from a random block. Blocks have HP; the panel on the right counts destroyed blocks on both sides.
- Hands and winner: each side is dealt 10 random blocks (`BattleHand.StartingSize`). A turn uses one block from each hand. Once the player's hand is empty the turns play by themselves. A side loses when it has no blocks on the grid and none in hand (`BattleCombat.GetOutcome`). The battle is a draw if both run out together or if the board looks exactly the same 3 times. RESET deals new hands.
- Attack animation: `BattleSlashEffect` plays the "Slash" frames between attacker and target. The frames come from `EffectFramesLoader` (permanent code in `Scripts/Core/`).
- **Slash frames are not in Git.** They were cut from a GIF supplied by Idan (`demon-awakening-effect-slash-3.gif`) whose source and license are not confirmed, so `Assets/StreamingAssets/Content/Effects/` is ignored by Git and exists only on Idan's PC. Without the frames the game draws a plain white streak. Replace them with art we own before any release.
- Each block's rules appear in a tooltip after the mouse rests on it for one second (palette or grid). The tooltip text is generated from the block list.
- Moving the mouse onto a placed block tints its area of effect: red for squares it attacks, blue for other effects (heal targets, and where a pushed block would land). The squares come from `BattleCombat.CollectAreaOfEffect`, which must be kept in step with the ability code beside it.
- Enemy: `BattleEnemy` looks one turn ahead. It tries each kind of block in its hand on each empty square, simulates the activation 6 times on a spare board, scores each result (4 points per block alive plus its HP, 6 extra for an orange block; its own count for, the player's against), averages, and picks the best, choosing at random between near-equal moves. It does not consider the player's reply. The numbers are constants at the top of the file.
- Activation order: the ORDER button switches between left to right (from a random block, in reading order) and random (all squares shuffled). Either way each square is visited once, and an orange retrigger does not count as a block's visit.
- Orange is the legendary block: every friend next to it uses its ability again, then every enemy on the grid takes 1 damage. Two orange blocks side by side do not trigger each other. It is dealt a quarter as often as the others (`DealWeight` in `BattleCubeKind.cs`). Its skin is a code-generated placeholder.
- Block rules: red -2 HP to each enemy next to it; blue pushes each enemy next to it one square (off the edge = destroyed, blocked = -1 HP); green +2 HP to each friend next to it; yellow -1 HP to every enemy in its row. The numbers are constants in `BattleCombat.cs` and the block list is in `BattleCubeKind.cs`; the rules note on the page is generated from them.
- The rules are plain C# (`BattleBoard`, `BattleBlock`, `BattleCombat`, `BattleEnemy`), separate from the screen code.
- Not done yet: no automated tests, the random numbers are not seeded (so a continued battle does not replay the same way), and block data is in C# instead of JSON.
- Mouse drag only. It does not support the "press to pick up, press to place" controller style that the real game will need.

- Idle animation: `BattleCell` bobs each block picture up and down (4 units, one bob every 1.2 seconds; constants at the top of the file). The bob is timed from `BattleBlock.PlacedAtSeconds`, which the screen sets when a block is placed, so blocks are out of step with each other.

## Battle items
- The item library is the column on the left of the battle screen. The rules are in `BattleItems` (plain C#); `BattleScreen` draws them. The enemy has no items.
- **Potion**: one use per battle. Clicking it makes the player's red (Strike) blocks remove `BattleItems.PotionStrikeBonus` (1) extra HP per hit until the end of that turn.
- **Gem**: a trinket that is always on. Before placing, the player can drag any blue (Push) block, their own or the enemy's, to any empty square, any number of times. The DELETE button under it throws the gem away for the rest of the battle; RESET brings it back. `BattleCell` handles the drag; `BattleDrag` holds the drag code shared with the hand.
- Item pictures live in `Assets/StreamingAssets/Content/Items/<Name>/<Name>.png` (Potion, Gem), loaded by `ItemIconLoader`. Size: 64 by 64 pixels, PNG, transparent background. Replace a file to change a picture. Both are original pixel art by Idan and are in Git.
- Not built yet: items as JSON data, more than two items, buying items in a shop.

## Known issues
- Fullscreen and resolution only take effect in a built game, not inside the Unity Editor.
- Settings does not yet match the full plan in CLAUDE.md section 6: no separate Music/SFX sliders or Audio Mixer, no VSync or frame-rate cap, no "Keep these settings?" prompt, no quality presets.
- Menu text is written directly in the scene and scripts. It should move to Unity's Localization package (needs that package added).
- UI text uses the legacy `Text` component, not TextMeshPro.
- No automated tests yet (there is no game logic to test so far).

## Global services
- `GameAudio`: the one sound player for music and effects. Created automatically when the game starts and kept across scenes.
